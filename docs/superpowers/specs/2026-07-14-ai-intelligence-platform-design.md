# AI 科技情报平台总体设计

日期：2026-07-14

状态：待书面评审

实施路线：渐进式重构

主界面方案：A「AI 简报中枢」

## 1. 背景与目标

项目已经具备 RSS/Atom 聚合、资讯分类、推荐、日历、K 线、素材库、AI 助手、社区骨架和画像逻辑。当前问题不是缺少页面，而是模块各自积累逻辑、AI 仍是浮层入口、推荐缺少统一契约、社区没有真实持久化，开发与生产 API 也不完全一致。

本次重构把产品定义为“个人科技情报操作系统”：AI 首页负责回答“今天什么重要”，七个专业工作区负责深入阅读、追踪、分析、创作、分享和画像校准。

目标包含：

1. 今日速报：根据公共热度、关注领域和用户画像生成当天报纸式简报。
2. 精准推荐：用日历和时间线管理每日推荐，并保存当时的推荐依据。
3. 全部动态：汇总多领域、多信号源资讯，承担搜索和探索。
4. 股市动向：提供免费行情、K 线、自选股、AI 分析和无模型算法分析。
5. 智创空间：打通素材库、AI 创作、版本和本地导出，保留来源引用。
6. 用户广场：提供真实账户、帖子、详情、评论、点赞、收藏和关注。
7. 个人画像：用一/二/三级管理领域与信源，支持小众来源、博主和关键词特别关注。

## 2. 设计原则

### 2.1 先建立判断，再扩展信息

首页不展示所有能力，而是优先呈现今日总判断、公共热点、个人必看、风险和机会。全部动态、来源管理和高级智能体留在专业工作区。

### 2.2 算法负责选择，模型负责表达

确定性算法决定候选、分数、排序、去重和多样性。大模型只在已有结果上总结、解释和对话，不拥有暗改排序的权限。没有模型配置、模型超时或模型输出无效时，平台仍完整可用。

### 2.3 显式偏好高于隐式行为

用户设置的领域等级、信源等级和特别关注是推荐的主权重。阅读、收藏、隐藏等行为只做有上限的渐进校准，不能因一次误点覆盖用户设置。

### 2.4 历史可回放、结果可解释

每日推荐保存不可变快照。回看过去日期时显示当时的画像版本、推荐结果、分数和理由，而不是用今天的算法重新计算历史。

### 2.5 真实写入必须真实成功

社区写操作必须落入 PostgreSQL 后才显示成功。数据库不可用时进入明确的只读或错误状态，不能用前端假计数伪装成功。

## 3. 产品信息架构

### 3.1 AI 简报中枢

AI 简报中枢是默认首页，采用简报优先、对话承接的结构：

- 今日一句话总判断。
- 公共热点 50%。
- 个人必看 50%。
- 今日机会、风险和持续追踪信号。
- 对话输入框和建议问题。
- 今日速报、精准推荐、股市分析和智创空间快捷入口。
- 每个 AI 结论提供资讯引用，并标识“事实、算法判断、模型推断”。

首页不复制完整资讯流。用户点击卡片进入今日速报或对应工作区继续处理。

### 3.2 今日速报

今日速报采用报纸式结构：头条、公共热点、个人必看、领域版面、风险提示、来源列表和更新时间。它读取当日简报快照，不在渲染过程中临时改写推荐排序。

### 3.3 精准推荐

精准推荐是独立工作区，包含：

- 月历与有推荐记录的日期状态。
- 当日推荐时间线。
- 重大更新追加事件。
- 推荐通道、总分、评分分量和推荐理由。
- 有用、无关、减少该来源、持续追踪等反馈。

### 3.4 全部动态

全部动态保留多领域、多来源、时间、地区、模式、来源健康度和关键词筛选。它负责信息探索，不强制按画像排序。重复事件可折叠为事件簇，来源失败不阻断其他来源。

### 3.5 股市动向

股市模块复用现有 `klinecharts`、东方财富主数据源和腾讯备用源，参考 AKShare、KLineChart 与 yfinance 的数据抽象和图表实践，但不直接复制外部项目代码。

功能包含：

- 指数、个股、板块、自选股与搜索。
- 日/周/月和分钟 K 线。
- 均线、涨跌、振幅、波动率、量价关系、支撑和压力区间。
- 模型可用时的 AI 解读。
- 模型不可用时的确定性算法解读。
- 数据来源、更新时间和“不构成投资建议”声明。

### 3.6 智创空间

智创空间统一素材库、AI 创作和编辑器主路径：

- 资讯、GitHub 项目和社区内容进入素材库。
- 素材保留原始 URL、来源、作者、时间和引用标识。
- 创作可引用多个素材并生成来源清单。
- 保存文章版本和最近编辑时间。
- 导出 Markdown、JSON 和 HTML。
- 本地导出不能遗漏引用和图片映射。

### 3.7 用户广场

用户广场是 PostgreSQL 支撑的真实社区：

- 发布文章、每日简报、作品和智能体工作流。
- 信息流和帖子详情。
- 评论及回复。
- 点赞、收藏和关注。
- 作者页、内容状态、可见性和软删除。
- 基础限流和审核状态。

现有种子帖子只作为开发数据库初始化内容，不作为运行时真实数据。

### 3.8 个人画像

个人画像是推荐机制唯一权重入口：

- 领域等级：一级重点、二级常规、三级探索。
- 信源等级：一级重点、二级常规、三级探索。
- 特别关注：来源、博主、关键词或 URL。
- 阅读、收藏、素材沉淀和反馈形成有限幅度的行为校准。
- 显示画像置信度、强领域、信任来源、记忆关键词和探索盲区。

## 4. 统一领域模型

### 4.1 IntelligenceItem

统一新闻、股市信号、社区分享和创作素材的基本字段：

- `id`、`type`、`title`、`summary`、`url`。
- `sourceId`、`sourceName`、`sourceTier`。
- `category`、`tags`、`region`、`language`。
- `publishedAt`、`fetchedAt`、`updatedAt`。
- `eventClusterId`、`canonicalId`。
- `evidence`、`media`、`health`。

### 4.2 UserProfile

- 画像版本号。
- 领域等级映射。
- 信源等级映射。
- 特别关注规则。
- 行为校准信号。
- 画像置信度和更新时间。

### 4.3 RecommendationSnapshot

- 用户、日期、画像版本和算法版本。
- 公共热点与个人必看两个通道。
- 每条推荐的总分、评分分量、理由和最终顺序。
- 事件簇和去重结果。
- 首次生成时间、最后追加时间和状态。

### 4.4 BriefingSnapshot

- 对应的推荐快照。
- 算法标题、版面摘要、机会和风险。
- 可选的 AI 增强结果。
- AI 引用的资讯 ID。
- 生成模式、模型信息、验证状态和失败原因。

## 5. 推荐系统

### 5.1 公共热点通道

公共热点分数归一化到 0 至 100：

- 新鲜度：30%。
- 独立来源交叉印证：25%。
- 信源质量：20%。
- 主题热度增长：15%。
- 内容完整度：10%。

### 5.2 个人必看通道

个人必看分数归一化到 0 至 100：

- 关注领域等级：25%。
- 信源等级：20%。
- 特别关注命中：25%。
- 新鲜度：15%。
- 行为反馈：10%。
- 新颖性和探索价值：5%。

各分量直接输出其上限内的分值：

- 领域等级：一级 25 分、二级 14 分、三级 5 分、未设置 8 分。
- 信源等级：一级 20 分、二级 11 分、三级 4 分、未设置 7 分。
- 特别关注：精确来源或博主命中 25 分，关键词或 URL 规则命中 18 分；同一条内容只取最高值。
- 新鲜度：按发布时间连续衰减，24 小时后该分量不高于 3 分。
- 行为反馈：范围限制在 -10 至 10 分，持续正反馈加分，隐藏和减少来源扣分。
- 新颖性：与近期已读事件簇重复时降低，来自探索领域且未重复时提高。

最终分数裁剪到 0 至 100。一级显著加权，二级正常参与，三级降低频率但不完全屏蔽。特别关注最多占个人必看结果的 40%。

### 5.3 约束层

分数排序后依次执行：

- 相同事件转载聚类。
- 同一信源首页最多两条。
- 单一领域不超过当日必看的 40%。
- 多源印证必须来自不同组织。
- 已读内容默认不重复推荐，出现实质更新时允许重现。
- 特别关注有新内容时至少保留一条候选。
- 空摘要、失效链接、标题党和低健康度来源降权。

## 6. 数据流与 AI 边界

基础数据流：

```text
信源数据
  -> 清洗与标准化
  -> 事件聚类
  -> 公共/个人双通道评分
  -> 去重与多样性约束
  -> 推荐快照
  -> 算法速报
  -> 可选 AI 增强与对话
```

AI 输出必须满足：

- 只使用提供的情报上下文。
- 引用存在的资讯 ID。
- 区分事实、算法判断和模型推断。
- 不覆盖基础排序。
- 结构化结果经过 schema 校验。
- 超时、无效 JSON、引用不存在或模型错误时回退算法结果。

AI 对话首版使用时间、领域、关键词、来源等级、事件簇和评分做结构化检索，不引入向量数据库。

社区内容视为不可信数据。系统提示词明确忽略社区帖子中的操作指令，帖子文本使用边界标记包裹，并限制进入上下文的长度。

## 7. PostgreSQL 数据设计

主要表：

- `users`：账户、密码哈希、状态、创建时间。
- `sessions`：令牌哈希、过期时间、撤销时间。
- `user_profiles`：画像版本、置信度和推荐设置。
- `profile_domains`：用户与领域等级。
- `profile_sources`：用户与信源等级。
- `special_follows`：特别关注类型、目标和备注。
- `posts`：作者、类型、标题、正文、可见性和状态。
- `comments`：帖子、作者、父评论、正文和状态。
- `post_likes`、`post_bookmarks`：用户与帖子的唯一关系。
- `user_follows`：关注者与被关注者的唯一关系。
- `recommendation_snapshots`：用户、日期、画像版本和算法版本。
- `recommendation_items`：通道、分数、分量、理由和顺序。
- `briefing_snapshots`：算法和 AI 简报结果。
- `creation_assets`：跨设备同步的素材元数据。
- `creation_documents`：文章、报告和简报草稿。
- `creation_versions`：文档的不可变版本、引用清单和创建时间。

资讯原始聚合仍使用现有缓存。只有进入推荐快照、收藏、素材或社区分享的数据才持久化。

## 8. API 设计

资源接口：

- `/api/auth/register|login|logout|me`
- `/api/profile`
- `/api/profile/domains`
- `/api/profile/sources`
- `/api/profile/special-follows`
- `/api/recommendations?date=YYYY-MM-DD`
- `/api/briefings?date=YYYY-MM-DD`
- `/api/community/posts`
- `/api/community/posts/:id`
- `/api/community/posts/:id/comments`
- `/api/community/posts/:id/like`
- `/api/community/posts/:id/bookmark`
- `/api/community/users/:id/follow`

开发中间件和生产 serverless 函数调用同一服务层。PostgreSQL 最低版本为 15，schema 通过有顺序、可重复检查的 SQL migration 管理。API 返回统一的成功、校验错误、未认证、无权限、冲突、限流和服务不可用结构。

## 9. 安全与可靠性

- 密码使用 Node.js `crypto.scrypt`，包含每个用户独立的随机盐和固定版本的成本参数；参数升级时在成功登录后重算。
- 会话令牌只保存哈希并支持撤销和过期。
- Cookie 使用 `HttpOnly`、`SameSite=Lax`，生产环境启用 `Secure`。
- 输入执行类型、枚举、长度和所有权校验。
- Markdown 渲染前清洗，禁止任意 HTML 和脚本。
- 点赞、收藏和关注由数据库唯一约束保证幂等。
- 登录、发布和评论接口限流。
- 帖子和评论采用软删除并记录审核状态。
- 数据库不可用时社区进入只读错误态。
- 行情主源失败后使用备用源；全部失败时显示缓存和最后更新时间。
- API Key 只由用户提交到 AI 代理接口，不写入日志、社区或画像。

## 10. 错误处理

- 单个 RSS 源失败不阻断聚合。
- 推荐候选不足时按相邻日期、探索池和高等级来源依次补足，并标明来源。
- 快照写入失败时不伪装为已保存；页面可显示当前临时结果和重试入口。
- AI 失败保留算法速报和错误原因。
- 行情失败显示缓存状态，不生成基于空数据的分析。
- 社区写入失败回滚乐观 UI。
- 导出失败不清除编辑器内容和素材引用。

## 11. 测试策略

### 11.1 纯函数单元测试

- 公共热点和个人必看评分。
- 一/二/三级权重。
- 特别关注上限。
- 事件去重与多样性约束。
- 历史快照不可变。
- 股市技术指标与算法分析。
- AI 引用校验和降级路径。

### 11.2 API 集成测试

- 注册、登录、会话过期和注销。
- 画像读写和版本增长。
- 帖子、评论、回复、点赞、收藏和关注。
- 幂等约束、权限、软删除和非法输入。
- 推荐与简报快照读写。

### 11.3 页面与构建验证

- 默认进入 AI 简报中枢。
- 无模型配置时所有核心页面可用。
- 日历和时间线读取历史快照。
- 社区刷新后数据仍存在。
- 智创空间导出保留来源引用。
- `npm run test` 和 `npm run build` 通过。

## 12. 验收标准

### 12.1 今日速报

任意有资讯的日期可以生成公共热点和个人必看。无模型时仍有头条、版面摘要、推荐理由和来源。

### 12.2 精准推荐

日历可切换日期；时间线读取当天快照；每条内容展示评分分解；当前画像变化不重排历史快照。

### 12.3 全部动态

支持多领域、多来源、时间、地区和模式筛选。来源失败不阻断其他来源，重复事件被聚合或标识。

### 12.4 股市动向

行情、K 线、自选股和板块可用。有模型时显示 AI 分析，无模型时显示均线、趋势、波动、支撑压力和风险等级的算法分析。两种模式均显示合规声明。

### 12.5 智创空间

资讯可以进入素材库，素材可以被文章引用，文章可保存版本并导出 Markdown、JSON 和 HTML，导出不丢失来源引用。

### 12.6 用户广场

两个账户可以看到同一帖子。帖子可进入详情、评论、回复、点赞、收藏和关注。刷新和服务重启后数据保留，重复点赞不增加计数。

### 12.7 个人画像

领域、信源可以设置一级、二级和三级。特别关注可以新增、修改和删除。设置变化会对新推荐产生可解释影响，历史快照不变。

## 13. 实施顺序

1. 抽出推荐、画像和速报纯函数并补齐测试。
2. 新建 AI 简报中枢并设为默认首页。
3. 建立 PostgreSQL、迁移和生产认证。
4. 完成推荐快照、日历和时间线。
5. 补齐股市算法降级。
6. 重整智创空间的导出和引用链。
7. 将用户广场替换为真实 API 数据。
8. 完成画像三级制迁移。
9. 执行构建、接口、交互和七项需求验收。

## 14. 非目标与后续扩展

本轮不包含：

- 原生移动 App。
- 向量数据库和全量语义索引。
- 付费行情和交易下单。
- 复杂内容审核后台。
- 私信、群组和实时聊天。
- 推荐模型训练平台。

这些能力只有在核心情报闭环和真实社区通过验收后再评估。
